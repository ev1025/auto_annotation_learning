# hdr_tonemap — 평가영상이 HDR(HLG) 이라 프레임이 밝고 뿌옇게 나오는 문제

2026-09-01 토르에서 돌린 확인 실험이다. 결론이 나왔으므로 코드를 레포에 남긴다.

## 무엇이 문제였나

평가영상 10개, 학습영상 37개(46개 중)가 **HLG HDR 10비트**로 촬영됐다.

```
pix_fmt=yuv420p10le · color_transfer=arib-std-b67(HLG) · color_space=bt2020nc
```

OpenCV·ffmpeg 는 HLG 를 SDR 로 변환하지 않고 그대로 뿌린다. 그래서 프레임을 뽑으면
플레이어로 볼 때보다 밝고 대비가 낮다. shim 의 볼트 구멍처럼 작은 형태가 눌린다.

측정(shim 라벨 박스 안, `Gearbox_shim.mp4` 110번 프레임)

| 처리 | 평균 | 표준편차 | 포화(>250) | 선명도(라플라시안 분산) |
|---|---|---|---|---|
| 변환 없음(지금) | 157.2 | 38.2 | 0.0% | 497.5 |
| 톤매핑 npl=100 | 167.3 | 48.3 | 17.0% | 878.0 |
| **톤매핑 npl=200** | 130.2 | **51.4** | 0.1% | **755.0** |
| 톤매핑 npl=400 | 101.1 | 43.1 | 0.0% | 535.4 |

기본값 npl=100 은 부품 영역의 17% 가 날아간다. `npl=200` 이 대비를 가장 살린다.

## 배포 모델로 확인한 효과

평가 프레임 715장을 변환 없음 / 톤매핑 npl=200 두 버전으로 만들어 같은 모델로 추론했다.

| 항목 | 변환 없음 | 톤매핑 npl=200 |
|---|---|---|
| 탐지된 프레임 | 355 | **384** |
| 등장 클래스 수 | 12 | **9** |
| r-ring·shim 이 같은 물체를 물은 프레임 | **9** | **2** |
| split_gearbox 검출 | 74 | **138** |

톤매핑 쪽이 낫다. 중복·유령 검출이 줄고 놓치던 장면을 잡는다. 단 GT 가 없는 상태의
간접 지표이므로, 사람 GT 로 mAP 를 재서 확정한 뒤 학습 프레임 재추출을 결정한다.
