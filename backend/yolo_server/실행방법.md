# YOLO 연동 테스트 서버 — 실행 방법

- 용도: 요청서 2탄 규격 그대로 동작하는 부품 인식 서버
- 오토러닝으로 학습한 **실제 부품 모델(2클래스: gearbox·a_test)** 을 서빙합니다
- 모델 파일 2종 동봉: **model.pt**(기본) · **model.onnx** — 실행에 인터넷 불필요 (설치 때만 필요)

## 1. 설치 (최초 1회)

- Python 3.10 이상 필요 (없으면 python.org 에서 설치, "Add to PATH" 체크)
- 이 폴더에서:

```
pip install -r requirements.txt
```

- GPU 없어도 됩니다 (CPU로 충분히 빠름)

## 2. 실행

- `run.bat` 더블클릭 (또는 `python server.py`)
- 창에 "준비 완료" 뜨면 서버 가동 중 → 창 닫으면 종료
- 처음 실행 시 Windows 방화벽 허용 창이 뜨면 **허용** (다른 기기에서 접속하려면 필수)

## 3. 접속 정보

| 항목 | 값 |
|---|---|
| 주소 | `http://<이 PC의 IP>:9412` |
| 감지 요청 | `POST /detect` (필드: `image`=JPEG, `camera_id`=기기ID) |
| 생존 확인 | `GET /health` |
| API 문서 | `http://<IP>:9412/docs` (Swagger — 필드 정의·예시 전부 있음) |

- PC IP 확인: cmd 에서 `ipconfig` → IPv4 주소

## 4. 부품 클래스표

오토러닝으로 학습한 **실제 부품 모델**입니다. 현재 2클래스:

| detection_class | detection_code | 테스트 방법 |
|---|---|---|
| `gearbox` | 0 | 카메라에 **기어박스**를 비추면 인식됨 |
| `a_test` | 1 | 카메라에 **a_test 부품**을 비추면 인식됨 |

- 앱의 "대상 부품 클래스"를 `gearbox` (또는 `a_test`)로 설정하면
  카메라에 해당 부품이 잡히는 순간 "인식됨" 이벤트가 발생합니다
- ⚠️ 클래스명은 소문자·밑줄까지 정확히: `gearbox`, `a_test`
- 부품이 추가되면 모델만 교체되며, 최신 클래스표는 언제든 `GET /health`로 확인 가능합니다

## 5. 동작 확인 (앱 없이)

```
curl http://localhost:9412/health
  → {"ok":true,"model":"model.pt","classes":{"0":"gearbox","1":"a_test"}}

curl -X POST http://localhost:9412/detect -F "image=@기어박스사진.jpg" -F "camera_id=TEST-01"
  → {"timestamp":"...","camera_id":"TEST-01","detection_count":1,
     "detections":[{"detection_class":"gearbox","detection_code":0,"confidence":0.9,
                    "bbox":{"x":...,"y":...,"w":...,"h":...}}]}
```

- 감지 없으면 `detection_count: 0` + 빈 배열 (정상 응답)
- 응답의 `bbox`는 규격 외 **추가 제공 필드**(박스 위치) — 무시해도 됩니다

## 6. 규격 요약 (요청서 2탄 준수)

- 감지 없어도 항상 200 + 동일 구조
- confidence 0.7 미만 미포함, number 3자리
- 오류: 400 `{"error":"invalid_image"}` / 500 `{"error":"inference_failed"}`
- 초당 3장 연속 POST 처리 여유 (처리 속도 실측치는 전달 시 안내)

## 7. 모델 형식 전환 (.pt ↔ .onnx)

- 기본은 **model.pt** (설치만으로 바로 동작, CPU 충분).
- **model.onnx** 로 바꾸려면 둘 중 하나:
  - 실행 시 환경변수: `set SERVE_MODEL_FILE=model.onnx` 후 `python server.py`
  - 또는 `server.py`의 `MODEL_PATH` 줄에서 `"model.pt"` → `"model.onnx"`
- onnx 실행에는 `onnxruntime`이 필요한데 `requirements.txt`에 이미 포함돼 있습니다.
- 나중에 GPU/Jetson 환경에서 속도가 필요하면 onnx(→TensorRT) 경로로 전환하세요. 응답 규격은 .pt/.onnx 동일합니다.

## 8. 모델 갱신

오토러닝으로 새 모델이 나오면 **같은 이름으로 덮어쓰고 서버만 재시작**하면 됩니다 (코드 수정 불필요):
- `model.pt` (그리고/또는 `model.onnx`) 파일만 새 것으로 교체 → `run.bat` 다시 실행.
